# Предзаказ по выбранной карточке Kaspi

`/crm/preorder` принимает ссылку карточки Kaspi или SKU, целую цену в тенге, срок и количество предзаказа (1–1 000 000, по умолчанию 5). Merchant SKU ищется точно в товарах и Тесте товара текущего магазина; старый XML-импорт с merchant SKU вместо master ID нормализуется с сохранением Product/FIFO; также поддерживается master ID и формат `masterId_suffix`. Неизвестный CRM SKU принимается в очередь: Product Test Agent 1.1.25 читает активные и архивные офферы кабинета и подтверждает связь merchant SKU → master ID до записи цены. Архивный оффер не требует публичной страницы перед восстановлением. Сохранённый URL карточки используется повторно. Город и зона доступны в той же форме; по умолчанию 196220100 / Magnum_ZONE1. Ранее продававшийся товар и уже существующий предзаказ переиспользуются, включая запись Теста товара, без дублирования истории.

Используется существующий Product Test Agent и его типы заданий `inspect` → `create_offer`. После успешного чтения backend ставит подключение в его очередь. Используется тот же агент и те же типы заданий; для архивного восстановления требуется обновление существующего Product Test Agent до 1.1.25. Старый runtime не получает ручные задания предзаказа, но продолжает остальные задания. Подключение уже существующего оффера использует прежнюю проверенную ветку восстановления Merchant Cabinet.

Запись CRM происходит после подтверждения Kaspi: выбранная карточка, настоящий Merchant SKU, точная цена, заданное количество, срок и доступность оффера. Совпадение числовых параметров у снятого с продажи оффера не считается успехом: он обязательно проходит process_offer на прежний SKU и проверку активности. История сохраняется в существующих ProductTestItem/Job и изолирована по workspace; не создаются фиктивные поставщики, закупочные цены или привязки Ozon. Старый товар повторно используется; его партии и идентификатор сохраняются. Подтверждённая цена/предзаказ добавляются в исходное и рабочее XML-зеркало при наличии активной выгрузки.

Товар виден в Fast Dumping с выключенной политикой. Это ручная публикация по заданной цене. В карточке можно настроить источник закупки или себестоимость и затем включить Fast/полную автоматизацию. Пока подключения нет, очередь не создаёт товар CRM. Текущие ошибки видны в новой вкладке; повторная отправка после завершения использует ту же запись.

Кнопка «Редактировать» в подключённой карточке (или карточке с ошибкой) открывает цену, срок и количество предзаказа. Если старый API-клиент не передаёт количество при редактировании, оно сохраняется. `PATCH /api/preorder/{item_id}` повторно использует ту же запись, город, зону и существующий pipeline агента. До подтверждения новой цены/срока Kaspi значение Fast State и XML остаётся прежним. Активный демпинг сначала нужно выключить; физический остаток и текущая незавершённая операция блокируют редактирование. Отдельный агент не требуется; используйте Product Test Agent 1.1.25.

Защиты: отказ для физического FIFO, активного Fast/классического демпинга и ещё не подтверждённых записей; повторная проверка перед выдачей задания агенту и перед регистрацией результата; смена настроек Fast/автоматизации запрещена на время подключения; повторные отправки одной карточки сериализуются. Ручная публикация снимает старое принудительное «в наличии» и автоматическое XML-восстановление классической политики. Приход товара уже во время выполняющегося внешнего запроса может потребовать отдельной сверки — итоговый результат не регистрируется при конфликте остатка.

При отказе соединения/редактирования причина теперь отображается рядом с кнопкой и внутри диалога, с сохранением введённых значений. Пока запрос выполняется, кнопка показывает «Отправляю…». Ответ 409 различает включённый Fast/автоматизацию, классический демпинг и незавершённую запись Kaspi. Для старой классической политики, чья страница перенаправляет в Fast Dumping, предусмотрена явная кнопка «Выключить классический демпинг»: `POST /api/preorder/products/{product_id}/stop-classic` использует обычную историю ручного выключения, сохраняет пороги и не изменяет оффер Kaspi. Товар проверяется в текущем workspace. Подключение необходимо повторить после выключения и завершения предыдущих операций.
